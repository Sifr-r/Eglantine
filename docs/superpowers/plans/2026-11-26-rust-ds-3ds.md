# Rust DS and 3DS Execution Implementation Plan

> Use the subagent-driven development skill. The DS and 3DS implementations can proceed in parallel.

**Goal.** Execute independently authored ARM programs loaded from NDS and 3DSX fixtures in two first-party Rust cores.

**Architecture.** Separate image validation, guest RAM, CPU state, and machine scheduling within each crate. Use std-only Rust 2021 and expose safe Rust entry points.

**Spec.** [Rust DS and 3DS design](../specs/2026-11-26-rust-ds-3ds-design.md)

## Contracts

Both packages expose `Machine::load(image: &[u8]) -> Result<Machine, LoadError>`, `Machine::step(&mut self) -> Result<(), ExecutionError>`, and `Machine::run_until(&mut self, max_steps: usize, stop: impl FnMut(&Self) -> bool) -> Result<RunOutcome, ExecutionError>`. Inspect the initial state and each completed step with the stop predicate. Report the number of completed steps and distinguish a satisfied condition from budget exhaustion. A guest fault ends the run with contextual error information. Expose read-only guest PC, register, and word-memory inspection.

Review the first instruction fetch, address arithmetic with oversized inputs, segment overlap, writes into read-only memory, and zero-step runs. Use standalone fixture bytes in tests. Keep production and test writes within the assigned crate.
