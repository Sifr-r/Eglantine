# Eglantine refactor report

23 November 2026 · Source snapshot `8d4b4ab565`

This report records findings at the audited revision. Use the [architecture task map](ARCHITECTURE.md#task-map) to locate the current implementation and the [ownership ledger](ARCHITECTURE.md#first-party-language-and-domain-ownership) for backend decisions. Recheck call paths and measurements before using a proposed change as a work item.

**The largest near-term size opportunity is the Windows download.** Keep MSVC debug symbols by build revision and package runtime files separately. For code and executable size, share the SMAA lookup tables and delete unreachable Vulkan graphics staging while preserving direct SM86 compute. For runtime performance, measure Vulkan readback and first-use pipeline waits before changing synchronization. The Switch 2 controller codec is the best first candidate for consolidating a parallel implementation after replay and hardware checks.

## Build footprint

**Windows packaging.** The MSVC release workflow uploads the whole bin directory and the release job zips the entire artifact. Release builds request `/DEBUG`. The two matching PDBs in the local build total **117.05 MiB raw**, or **about 33.0 MiB** in a level-6 DEFLATE estimate. Confirm the release archive contents before counting savings. Stage a runtime-only ZIP and retain matching symbols separately for crash diagnosis. The CMake post-link step and the MSVC CI job currently both run `windeployqt` with different options. Give one step ownership of the staged runtime files, then launch both frontends and exercise the updater from a clean extracted release or daily ZIP. [MSVC flags](src/CMakeLists.txt) · [CMake deployment](src/yuzu/CMakeLists.txt) · [Updater build](.github/workflows/build-windows.yml) · [Windows artifact](.github/workflows/build-windows.yml) · [Release ZIP](.github/workflows/release.yml)

**Start compile-time work at the Ampere lowerer.** The public lowering header is about 4,200 lines. The local Ninja dependency index lists 34 consuming first-party objects across tests, video core and CLI. Move the large non-template implementation into the shader recompiler, keep declarations and types in the header, and preserve linkage for the standalone shader triage tools. Compare clean compile time and object rebuild counts after an implementation-only edit. Run the Ampere and Rust differential tests and smoke the standalone tools. [Lowering implementation](src/shader_recompiler/frontend/ampere/lower_to_maxwell.h) · [Transitive include](src/video_core/shader_environment.h) · [Standalone dump tool](tools/nx2/lower_dump.cpp)

**Qt Charts is an optional second packaging reduction.** The desktop target links it for the FPS overlay. Replacing the single bounded chart with a Qt Widgets plot could remove the module from the build and package. The existing Windows DLL is 1.69 MiB raw. Keep the overlay’s axes, values, drag behavior and accessibility, and compare runtime dependencies and ZIP size before committing to the replacement. [Qt configuration](CMakeLists.txt) · [Desktop linkage](src/yuzu/CMakeLists.txt) · [Performance overlay](src/yuzu/render/performance_overlay.cpp)

With any of the four CMake Rust options on, CMake builds `eglantine_ffi`, its manifest requires all four backend crates, and its library anchors their exported entry points. Match the CMake switches to optional Cargo dependencies and feature-gated export anchors if maintaining partial Rust builds is a supported goal. Compare clean and incremental build time, Cargo graph, `.text`/`.rdata` sizes and packaged bytes for all-on, all-off and single-backend builds. Preserve the unified static-library contract and platform linker requirements. Executable savings need a link-map or section-size comparison because archive contents and final linkage are different measurements.
